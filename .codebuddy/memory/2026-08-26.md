# 2026-08-26

## IMAP 同步 0 条邮件问题修复

**现象**: 用户添加第二个 QQ 邮箱(mma1987@imap.qq.com)，初始同步 INBOX 时后端日志显示 `1617 UIDs found (search=SINCE 25-Aug-2025)` 但 `fetched 0 messages`，前端收件箱无邮件。

**根因**: `src-tauri/src/imap/client.rs` 的 `fetch_uid_batches`(批量 UID FETCH，用于初始同步)在 async-imap 库的 stream 解析器对某些 QQ 邮箱响应返回空 Vec 时，会静默返回 0 而不报错。已有的单邮件 fetch 路径(`fetch_message_body` ~line 498)有 `ASYNC_IMAP_EMPTY` fallback 到 raw TCP，但 `fetch_uid_batches` 和 `sync_folder_with_batches` 没有同样的 fallback。

**修复**: 在 `src-tauri/src/commands.rs` 的 `imap_sync_folder_streaming` 命令中，async-imap 路径返回后检测 `messages_fetched == 0 && !uids.is_empty()`，自动 fallback 到 `raw_sync_folder_with_batches`(raw TCP 路径)。为支持闭包二次传递，把 `emit_batch` 重构为 `make_emit_batch()` 工厂。

**关键文件**:
- `src-tauri/src/commands.rs` `imap_sync_folder_streaming` (~line 285)
- `src-tauri/src/imap/client.rs` `fetch_uid_batches` (~line 1224), `sync_folder_with_batches` (~line 1320), `raw_sync_folder_with_batches` (~line 1425), `prefer_raw_imap_fetch` (~line 13, 目前只对 yandex-team/yandex.ru 返回 true)

## 二次问题: 同步成功但点击邮件 "UID not found"

**现象**: fallback 后 raw sync 把邮件存入 DB(含 imap_uid=21932)，但点击邮件时前端报 `Failed to load message body: Message UID 21932 not found in INBOX`，一闪而过显示内容后又消失。

**根因**: `fetch_message_body_resolved` 已经有 `ASYNC_IMAP_EMPTY` fallback 路径，但 `fetch_message_body` (单邮件 fetch) 没有同样的检测 —— 当 async-imap 对 QQ 邮箱的 UID FETCH 返回空 stream 时，它直接报"not found"而不是返回 `ASYNC_IMAP_EMPTY:` 错误，导致 fallback 不触发。

**修复**: 在 `fetch_message_body` (client.rs:428) SELECT 后保留 mailbox 信息，当 `fetches.is_empty() && mailbox.exists > 0` 时返回 `ASYNC_IMAP_EMPTY:{folder}` 错误，让 `fetch_message_body_resolved` 走 raw fallback。
