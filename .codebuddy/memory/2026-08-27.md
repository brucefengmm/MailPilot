## 修复 QQ 邮箱增量同步收不到新邮件

现象：QQ 邮箱（mma1987@imap.qq.com）有 2 封新邮件，自动刷新和手动刷新都收不到。
根因（两处，均在 `src-tauri/src/imap/client.rs`）：
1. `delta_check_folders` 用 `UID SEARCH {last_uid+1}:*`，QQ 的 async-imap 解析器对 `:*` 上界返回空集合。
   - 修复：上界改 `4294967295`；range 失败时 fallback 到 `UID SEARCH ALL` + 客户端过滤 `> last_uid`。
2. `fetch_messages_batched` 只对 yandex 走 raw TCP，QQ 走 async-imap 批量 fetch 返回空（同初始同步问题）。
   - 修复：`prefer_raw_imap_fetch` 增加 `qq.com` / `imap.qq.com`，QQ 增量与单邮件 fetch 均走 raw TCP。

注意：初始同步 fallback（commands.rs `imap_sync_folder_streaming`）已存在，本次只补增量路径。
编译：`cargo build` 通过（dev server 占用 exe 导致链接"拒绝访问"属正常，需重启 app 生效）。
日志增强：`delta_check_folders` range 成功路径加 `log::info!`（缓存的 `uids.len()` 存到 `raw_count` 避免 borrow after move）。

## QQ 增量同步二次修复（range 成功但返空）

实测日志证据：`UID SEARCH 21934:4294967295 INBOX: range returned 0 uids`。
发现 QQ 的 async-imap `uid_search` 对**任何带 UID range 的查询**（无论 `:*` 还是 `:4294967295`）都返回空集合（`Ok(Ok(empty))`，不是报错）。
之前修复只在 range 报错（`Ok(Err)`）时 fallback 到 ALL，漏了"成功但空"。
新修复：`delta_check_folders` 加 `host: &str` 参数；range 返 0 且 `prefer_raw_imap_fetch(host)` 且 `last_uid > 0` 时，自动 fallback 到 `UID SEARCH ALL` + 客户端过滤。
调用方两处都更新传 `&config.host`：`run_delta_sync`（client.rs）和 `imap_delta_check`（commands.rs）。
yandex range 正常工作不退化（不会被误触发 ALL）。

## QQ 增量同步三次验证 + Gmail 同步机制对比

实测成功：日志 `delta_check: ALL fallback for INBOX: 4 new after filter` → raw fetch 拉到 UID 21934-21937 → parser 成功解析。完整链路打通。

### Gmail vs IMAP 同步机制对比
- Gmail 用 History API（`users.history.list`），事件驱动：messagesAdded/Deleted/labelsAdded/Removed。
- 全账号一个 `historyId`；IMAP 是每文件夹独立 `last_uid`。
- Gmail historyId 过期返 404 → 抛 `HISTORY_EXPIRED` → 上层触发 full re-sync（优雅降级）。
- Gmail 有 `pendingOps` 本地操作保护（sync.ts:357-360），IMAP 路径无。
- Gmail 用 `parallelLimit(10)` 并发 re-fetch thread；IMAP fetch 串行 batch。
- 代码位置：`src/services/gmail/sync.ts:288 deltaSync`、`src/services/gmail/syncManager.ts`。

### IMAP 路径潜在优化方向
1. 短期：重命名 `prefer_raw_imap_fetch` → `async_imap_unreliable`（函数名更准确，复用于 fetch 和 search fallback 两处）。
2. 中期：IMAP fetch 并发化（借鉴 Gmail parallelLimit）。
3. 中期：加 pendingOps 保护避免覆盖本地修改。
4. 长期：IMAP IDLE 实现真推送（QQ/yandex/gmail 都支持）。
5. 长期：客户端检测删除（EXISTS 数量变化 → FETCH FLAGS 比对）。

## Homebrew Tap 配置要点

`update-homebrew.yml` 自动维护 macOS Homebrew Cask（`mailpilot.rb`）：
- Tap 仓库：`brucefengmm/homebrew-mailpilot`（public，含 `Casks/mailpilot.rb`）
